# 写作技能

Vibepost 有两个内置技能，App 自带、只读、AI 每一轮都用，不用选（按题材挑着用的内置写作手册见后面的「写作手册」）：

| 技能 | 文件 | 管什么 |
| --- | --- | --- |
| 使用 Vibepost | `src/engine/manual.js`（生成 [manual.md](manual.md)） | App 认得的块样式、组件、记号，什么时候用哪种，排版经验 |
| 写作 | [`src/skills/写作.md`](../src/skills/写作.md) | 怎么写才像一个真人在讲自己的事 |

## 写作技能从哪来

起因是 AI 写的稿子 AI 味太重，作者自己写的却像人写的。照女娲（huashu-nuwa）的提炼办法对比了两边的文字和作者对 AI 稿子的反馈，结论是四件事：讲一件真事、按发生的顺序讲、用自己的话、不升华。

- **表达方式取自作者本人**：他写的一篇帖子（建了个网站、在后台看到爬虫、做了个小实验）和他口述的稿子，对比同期 AI 的稿子。差别能数出来：他每千字三十多个「我」、十来个「你 / 大家」，AI 的资讯稿两项都是零；AI 排卡片时冒号的密度是他的十倍（「标签：内容」一句接一句）；他一个「首先 / 此外 / 值得注意」都不用，靠「然后」「后面」「所以」顺着时间往下走；中英夹杂是他的常态，不是要修的毛病。
- **规则取自作者的反馈**：过程要讲全（「你自己懂了，别人不懂」），失败的版本要写（「人家要看到你整个的心路历程」），不夸张，转述别人的事时不加判断、不加猜测（「感觉这个事情跟一个谣言一样」）。
- **写法取自特稿与非虚构**：从事件中间切入，用场景和动作代替概括，主题从故事里析出而不是先喊出来，克制收尾。
- **三处张力照实写进技能**：转述不加判断、亲历全是判断（看素材是不是自己的经历）；少堆数字、帖子里数字却很多（数字当证据，不当成绩单）；要精简又要啰嗦（合并重复的结构，不删推理和例子）。

它是「主题技能」，不是角色扮演：不让 AI 模仿作者的口癖去改别人的稿子。用户自己写的话原样保留，别人的稿子不往里加任何人的口癖。例子用作者帖子里的句子或生活里的小事。

调研材料（量化对比、反馈原话、外部写法的出处）只在作者本机，不进仓库。

## 怎么用上

- **App 里的 AI**：说明书（`src/ai/session.js`）带两份的短版，写作的短版是技能里 `## 最要紧的几条` 那一节；工作副本的 `AGENTS.md` 是两份全文（操作手册在前、写作在后，`MediaCraftSkills.agentsFile()`），后面接用户写作手册的目录。两只壳照旧把页面给的 `agentsFile` 写进去，不用改。
- **一键润色、改写选中、预设**：润色只修错字、读不通、指代不清；改写选中不再要「更有感染力」；封面标题、首图文案、去 AI 味、写小红书正文、精简都照技能的说法（`src/ai/presets.js`）。
- **外部 Agent**：`get_writing_skill` 读全文，握手说明带写作的短版（App 开着时），配套的 Claude Code 技能 [skills/vibepost](../skills/vibepost/SKILL.md) 开头就让 Agent 读两份。
- **AI 设置 › 内置技能**：列出两份，「查看」展开全文，只读。

改了 `src/skills/写作.md` 或 `src/skills/手册/*.md` 要运行 `node scripts/build-skills.mjs` 重新生成登记表 `src/skills/index.js`（提交进仓库，`SkillsTests` 比对不过期）。

## 写作手册

写作手册补充某类题材的口味（读者、取材、结构），不是每轮都用：AI 按这篇的题材挑一份，用户也可以点名。和写作技能冲突时照写作技能，除非用户这一轮点名要。有两处：

- **内置的四份**（`src/skills/手册/*.md`，和技能一起登记在 `src/skills/index.js`）：经验分享、教程攻略、测评种草、论文与技术解读。App 自带、只读、随 App 更新。只写这类稿子要先问清的素材、结构和容易出的毛病，不重复写作技能，不带任何人的口癖，不引用第三方的写法。
- **用户自己的**：`.md` 文件，放在支持目录的 `写作手册/`（格式与规则见 [storage.md](storage.md#写作手册写作手册)）。

两处由页面的 `MediaCraftManualLibrary`（`src/skills/skills.js`）合在一起：用户的手册和内置的同名时用用户那份。所以定制一份内置手册就是存一份同名的：AI 设置里点「复制一份来改」，或让 AI 用 `save_writing_manual` 存同名的一份；删掉那个文件就回到内置的。快捷命令「存成我的写作手册」让 AI 把当前这篇的写法提炼成一份新手册（保存前弹确认框）。

- AI 每轮按题材自己挑；也可以在输入框旁点「写作手册」，或在空输入框按 `/`（⌘⇧K），搜索并多选几份，只随下一条消息发送，历史里显示当时的选择。
- App 不往用户的文件夹里放东西：第一次用时只建一个空文件夹，也从不删里面的文件。内置的四份随 App 走，不在这个文件夹里。
- App 里的 AI 每轮在 `AGENTS.md` 里拿到没被盖住的内置手册全文（「# 内置写作手册」一节，接在两份技能后面），用户的手册照旧拷进工作副本的 `写作手册/`、目录在最后；外部 Agent 的 `list_writing_manuals` 把两处列在一起，内置的标「（内置）」。

0.8.0 曾往用户的文件夹里放七份示例手册（小红书图文、国际新闻、代码库解读、标题打磨、保留原意去 AI 味、观点长文、英文简明表达），0.8.1 都去掉了：有用的写法并进了写作技能（标题部分重新写过，不再照搬 title-matrix，随包的 MIT 许可文件也一起去掉）。老用户文件夹里已经装好的那几份照样是用户的手册，照常列出、可选，App 不删也不再往里加。
