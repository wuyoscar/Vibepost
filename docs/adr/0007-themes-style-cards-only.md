# 0007：主题只管卡片，界面跟随系统浅色 / 深色

- 状态：已采纳（2026-09-30），取代 [ADR 0003](0003-theme-bundles-ui-and-card.md) 里「主题同时决定界面皮肤」那一条

## 背景

ADR 0003 让一个主题同时换界面皮肤、卡片结构与配色，8 个主题各带一套界面令牌。用下来的问题：卡片想要的颜色（纸感、纯黑、强调色很重）不一定适合当编辑器界面；换一篇稿子界面就跟着变，写作时的环境不稳定；每加一个主题都要多维护一整套界面令牌。Oscar 的判断是界面现在的颜色（「灰」那套）挺好，要重做的是卡片。

## 决定

- 主题只决定卡片：卡片结构、卡片配色（五个角色）、字体选「跟随主题」时的字体。每篇稿子记住自己的主题，新稿子沿用上次选的，这些都不变。
- 界面皮肤只有两套：浅色（原「灰」的令牌）与深色（原「暗夜」的令牌），跟随系统外观（`prefers-color-scheme`）。`src/motion.js` 在 `<head>` 里载入，页面画出来之前就写上 `<html data-ui-theme="light" | "dark">`，系统一切换就带过渡地换过去。
  - 2026-11-16 补：两套皮肤的值换过一轮（中性色、半透明细线，玻璃由 `.app` 一层画），不再是「灰」和「暗夜」那两套值；还是两套、跟随系统，这条决定没变。
- 窗口（原生毛玻璃、红绿灯）的深浅也跟随系统：页面不再把自己的深浅报给壳，壳不再设置窗口外观——否则两边互相钉住，系统切换后谁都不会变。
- 当前稿子的主题写在 `<html data-card-theme>`，主题面板靠它立即标出当前主题。

## 后果

- 卡片主题可以放开设计，不用顾及它当界面好不好看；重做主题（v5 第 02、03 张票）不再牵动界面。
- 用户没法手动选界面深浅，只能跟随系统（少一个选项，符合「不给太多选择」）。
- 测试把窗口外观固定在浅色，需要深色的测试自己切换（`ShellHarness.setAppearance`）。
