# Vibepost 操作手册

Vibepost 把一篇 Markdown 排成小红书的图文卡片（也能排成公众号长文）。这份手册只讲 App 认得的写法与排版经验，跟用哪个模型无关；写什么内容、什么口味看写作手册。

- 每一行在卡片上另起一行，空行分段；放不下自动换到下一张。
- 下面的中文写法是规范写法，英文写法（`:::kicker`、`[[image:…]]`、`{{color:…|…}}`）也照样认，App 收下稿子时会换成中文。
- 代码块、行内代码里的记号只是文字。

## 块样式

一块就是空行隔开的一段（或一个组件）。在编辑器左上角「样式」、卡片上点选一块后的「换样式」里都能换；同一类里互换（段落类在段落类里，列表类在列表类里），列表也能拆回正文。

| 样式 | 写法 | 是什么 | 什么时候用 |
| --- | --- | --- | --- |
| 正文 | 直接写 | 普通的一段话 | 用在大多数内容 |
| 大标题 | `# 文字` | 这一页最大的字 | 用在一篇的主标题、一页的大字；一页里只放一个 |
| 小标题 | `## 文字` | 分段的标题 | 用在把一页分成几段 |
| 三级标题 | `### 文字` | 最小一级的标题 | 用在章节名、一条资讯的标题 |
| 引用 | `> 文字` | 别人说的话，左边一条竖线 | 用在原话、摘录 |
| 小标签 | `:::小标签` … `:::` | 标题上方或旁边的一行小字 | 用在来源、论文名、栏目名、日期；章节名用三级标题，不用小标签 |
| 提示 | `:::提示` … `:::` | 带底色的一块提示 | 用在结论、要点、注意事项 |
| 页尾 | `:::页尾` … `:::` | 这一页最底下的一行小字 | 用在出处、图片来源、免责声明：放在这一页的最后一块；写在页中间只会原地显示成小字、不贴底；论文名用小标签 |
| 等宽 | `:::等宽` … `:::` | 等宽字体的一块，空格与对齐照原样 | 用在 prompt、命令、需要对齐的文字 |
| 无序列表 | `- 一项` | 圆点开头的几项 | 用在并列的几点 |
| 有序列表 | `1. 第一项` | 带编号的几项 | 用在有先后、要数清楚的几点 |
| 标签列表 | `:::标签列表` … `:::` | 每项开头一个彩色胶囊标签（写成 [类别]） | 用在分类、对比、清单 |
| 步骤 | `:::步骤` … `:::` | 自动编号的步骤 | 用在操作步骤、流程 |

## 组件

单独一行 `:::名字` 开头、单独一行 `:::` 收尾，中间照常写 Markdown（可以嵌套）；没有收尾时按普通文字显示。
对齐写在名字后面：`:::提示 居中`、`:::提示 靠右`（靠左是默认，不用写）。认不出的名字不报错，渲染成 `class="mc-c c-名字"` 的容器，留给这篇的卡片样式。

### 小标签（kicker）

标题上方或旁边的一行小字。用在来源、论文名、栏目名、日期；章节名用三级标题，不用小标签。

```
:::小标签
论文：When Do Models Admit They Are Wrong?
:::
```

### 提示（note）

带底色的一块提示。用在结论、要点、注意事项。

```
:::提示
所有问题放在同一个请求里并行发出。
:::
```

### 页尾（footnote）

这一页最底下的一行小字。用在出处、图片来源、免责声明：放在这一页的最后一块；写在页中间只会原地显示成小字、不贴底；论文名用小标签。

```
:::页尾
图片来源：作者自摄
:::
```

### 等宽（mono）

等宽字体的一块，空格与对齐照原样。用在 prompt、命令、需要对齐的文字。

```
:::等宽
You are a helpful assistant.
:::
```

### 标签列表（rows）

每项开头一个彩色胶囊标签（写成 [类别]）。用在分类、对比、清单。

```
:::标签列表
- [保留] 一句话说清楚要做什么
- [删掉] 「只输出 JSON」这类格式指令
:::
```

### 步骤（steps）

自动编号的步骤。用在操作步骤、流程。

```
:::步骤
- 先把问题拆开
- 每一块单独问
- 最后合起来
:::
```

## 记号

- 图片 `[[图片:编号]]`：一张图或一段实况，独占一行；编号由 App 生成：插图、拖进图片时自动写，不用手写。
- 拼图 `[[图片:甲|乙]]`、`[[图片:甲|乙|4x3]]`：两张图并排，独占一行；比例 1x1、4x3、3x2、16x9（不写就是 16x9）。
- 分页 `[[分页]]`：独占一行，后面的内容从下一张卡片开始；也可以按 ⌘↩。
- 结尾页 `[[结尾]]`：独占一行，后面的内容排成结尾页（居中、留白，最后是署名）；关注引导、下期预告写在它后面。
- 字色 `{{字色:#d9480f|文字}}`：给几个字换颜色；选中文字用浮动条点一下最省事。
- 高亮 `{{高亮:#fff3bf|文字}}`：给几个字加底色。
- 下划线 `{{下划线:实线|文字}}`、`{{下划线:虚线|文字}}`：实线或虚线的下划线。
- 标注 `{{标注:类别|文字}}`：按类别上色；同一个类别在一篇里颜色固定，标签列表里同名的 [类别] 也是这个颜色。

- 记号要照原样保留：改稿时不要改写、翻译、挪动或删掉它们（换样式、挪图片用 App 的工具）。
- 冒号、竖线两侧不加空格；色值是 `#` 加 3–8 位十六进制数。

## 行内格式

`**加粗**` 加粗、`*斜体*` 斜体、`~~删除线~~` 删除线、`` `代码` `` 行内代码、`[文字](https://…)` 链接；标题 `#`、引用 `>`、列表 `-` / `1.`、表格、分割线 `---` 照常写。

## 排版经验

- 来源、论文名这类挂在标题旁边的小字用小标签，不用页尾。
- 页尾只放在一页的最后一块（出处、免责声明）；写在中间不贴底，只是原地的一行小字。
- 章节名用三级标题。标题会带着后面第一段一起换页，不要让一页只剩一个章节名。
- 一张卡片 180–280 字最好读，超过 300 字偏挤。一条一页（每条后面写 [[分页]]）时，溢出就收紧文字或拆成两页，太空就和上一条并成一页。
- 颜色少而有用：同一类的词用同一个标注，关键的一句放提示框；不要整段上色。
- 块与块之间的距离是这篇的段距（检查器「版式 › 段距」，set_style 的 blockGap，默认 0.55 行）；觉得太空就调小，不要靠连续空行、空段落或多余的 [[分页]] 撑开或拉开间距。
- 排完版看一遍每页的问题（只有标题、太空、溢出），逐页处理好再交差。

## 片段

写好的几段示范文字，在「插入」与「/」菜单的「片段」一组里：点一下插到光标处（一次 ⌘Z 撤回），改成自己的内容就行。插在非空行后自动隔开空行；开头、结尾的 [[分页]] 挨着已有的分页或稿子头尾时自动去掉；含 [[结尾]] 的只能插在稿子末尾，一篇只能有一个。Agent 用工具 insert_section 插（snippet 给下面括号里的 id 或名字，位置给 before / after 的原文或 position 的 start / end；也能给自己写的一段 markdown），同样的规则、一步可撤销。片段里没有图片，配图另用插图的工具。

### 三步教程（tutorial）

三步做成一件事的小教程。用在操作教程、方法分享。

```
## 三步把一篇论文读薄

:::步骤
- 先读摘要和结论，用一句话写下它要解决什么问题
- 只看图表：每张图回答了哪个问题、数据从哪来
- 回到方法部分，补上第一步里没说清的地方
:::
```

### 对比（compare）

优点、缺点各几条的对比。用在选型、要不要买、两种做法比一比。

```
## 本地跑模型还是用 API

:::标签列表
- [优点] 数据不出本机，断网也能用
- [优点] 跑得越多越划算，没有按量计费
- [缺点] 显存决定上限，大模型跑不起来
- [缺点] 换新模型要自己下载、自己调
:::
```

### 金句页（quote-page）

单独一页的大字金句加一句出处。用在一篇的转折处、想让人截图的那句话。

```
[[分页]]

# 写不出来，往往是因为还没想清楚

> 把想法说给一个外行听，说不明白的地方就是文章的空洞。

[[分页]]
```

### 论文卡（paper）

一篇论文的小标题、原名与两段解读。用在论文解读、读书笔记。

```
## 模型会承认自己错了吗

:::小标签
论文：When Do Models Admit They Are Wrong?
:::

研究者让模型先回答，再给出一条反驳，看它会不会改口。结果是：反驳越具体，模型越容易放弃原本正确的答案。

这说明「承认错误」和「判断对错」是两回事。想让模型可靠，不能只教它顺从，还要让它分得清哪些反驳站得住。
```

### 时间线（timeline）

按日期排的几件事。用在事件回顾、新闻的来龙去脉。

```
## 这件事的来龙去脉

1. 3 月 12 日：论文上线 arXiv，当天只有几十次下载
2. 3 月 20 日：一位博主写了解读，转发破万
3. 4 月 2 日：作者公开代码，社区开始复现
4. 4 月 15 日：复现结果出来，核心结论站住了
```

### FAQ（faq）

三个常见问题与回答。用在答疑、避坑指南。

```
### 需要先学编程吗

不用。先照着做出第一个结果，遇到看不懂的再查，比先学完再动手快得多。

### 一天花多少时间合适

半小时就够。关键是每天都碰一下，断了三天就得从头找感觉。

### 卡住了怎么办

把问题原样写下来发给 AI 或论坛。写清楚问题的过程，一半时候自己就想通了。
```

### 清单（checklist）

一张检查清单加一条提示。用在发布前检查、行前准备、避坑要点。

```
## 发布前最后一遍检查

- 标题不超过 20 个字，含一个具体的数字或场景
- 第一张卡片一眼能看出这篇讲什么
- 每张卡片不超过 300 字，没有只有标题的页
- 图片都换成了自己的，没有占位图
- 正文里写了话题，不超过 5 个

:::提示
发布前把每张卡片放到手机上看一遍：电脑上好看不等于手机上好看。
:::
```

### 前后对比（before-after）

改前、改后一张表。用在改稿、改图、改方案前后的变化。

```
## 改前改后

| 项目 | 改前 | 改后 |
| --- | --- | --- |
| 标题 | 关于学习方法的一些思考 | 我用这 3 个方法把阅读速度翻了一倍 |
| 首图 | 一张风景照 | 带结论的大字卡片 |
| 结尾 | 没有 | 一句引导加下期预告 |
```

### 数据卡（data）

对齐的几行数字加一句结论。用在周报、战报、实测数据。

```
## 这周的数字

:::等宽
阅读  12,480  ↑ 36%
点赞     893  ↑ 12%
收藏     412  ↑ 58%
涨粉     176  ↑ 21%
:::

收藏涨得最快：实用清单类的内容值得多做几篇。
```

### 结尾引导（ending）

结尾页：下期预告与关注、收藏引导。用在一篇的最后（稿子里还没有结尾页时）。

```
[[结尾]]

## 下期预告

讲讲怎么用 AI 把一篇论文整理成这样的卡片。

觉得有用就点个收藏，关注我不错过下一期。
```
