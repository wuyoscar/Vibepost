# 用 Vibepost 做一篇小红书

目标：你收集信息、写稿、在 Vibepost 里排好版并逐页检查；用户只在 App 里看一眼、改几个字、点发送。
Vibepost 的工具都以 `mcp__mediacraft__` 开头；没有这些工具时，告诉用户先在终端运行一次
`claude mcp add mediacraft -- "/Applications/Vibepost.app/Contents/MacOS/mediacraft-mcp"`（App 里 AI 助手 › 设置 ›「复制接入命令」有同样的一行），并在同一处打开「允许外部 Agent 连接」（默认是关的），再开一个新会话。

工具改的是 App 里正在编辑的稿子，用户眼前马上变，每一步都能 ⌘Z 撤销，也列在 AI 助手的「外部 Agent 的操作」里。

开始前先 `get_manual` 读一遍操作手册（块样式、组件、记号的写法与排版经验，也在仓库的 docs/manual.md）：这份技能只讲流程，写法以手册为准。

## 1. 调研

- 用你手边的搜索与抓取工具（网页搜索、用户装的技能）找 3–5 个可靠来源，记下要点、数字和出处；拿不准的事实不写，或写明「据 X 报道」。
- 先想清楚这篇给谁看、看完能带走什么（一句话），再决定要点：图文卡片一张讲一件事，通常 4–8 张。

## 2. 写稿（create_draft / update_draft）

- 一篇笔记分三部分：`title` 标题、`markdown` 卡片内容（排在一张张图片上的字）、`caption` 小红书正文（发布时图片下面的那段纯文本，#话题 写在这里）。
- `create_draft` 一次给 `title`、`markdown` 与 `caption`（新稿子沿用用户上次选的主题）；之后改稿用 `update_draft`，**卡片内容整篇替换**，只改一处也要给完整内容，先 `get_draft` 拿到当前的（用户可能刚在 App 里改过）。
- 标题 ≤ 20 字，具体、有信息量，不标题党。正文口语、短句，每段 1–3 行；全篇一般 300–800 字。
- 结构：第一张是钩子（标题 + 一两句为什么值得看），中间每张一个要点（小标题 `##` + 两三行说明或列表），最后一张总结或行动建议。
- 小红书正文（`caption`）：纯文本、口语，200–500 字，不照抄卡片上的字，最后一行 3–5 个话题标签（`#话题 #话题`），不超过 1000 字。
- 写法看操作手册（`get_manual`）：每一行在卡片上另起一行，空行分段；块样式（标题、引用、`:::小标签`、`:::提示` 这类组件）、
  记号（`[[分页]]`、`{{字色:#d9480f|字}}`……）都用中文写法（英文写法也认，App 收下时换成中文）。
  图片不要自己写 `[[图片:…]]`：本机图片用 `import_images`（绝对路径，可以给 `after` 定位到某段原文之后）。
- 写什么内容、什么口味看写作手册：`list_writing_manuals` 列出名字和说明，按这篇写什么挑一份（用户点名了就用那份），`read_writing_manual` 读全文。
  用户要把这次的经验记进写作手册（或新建一份）时用 `save_writing_manual` 整份交过去，App 弹确认框，用户同意才保存。
- 内置说明书（`list_drafts` 里 builtIn）只读，不要改它；要改先新建。

## 3. 挑样式（set_theme / apply_palette / set_style）

- 主题（`set_theme`，id 或中文名）决定卡片结构与配色：备忘 `notes`（干净的随手记、黄色小签，默认）、纯白 `plain`（白底黑线、极简）、手帐 `journal`（文楷、薄荷胶带）、柔光 `glow`（淡紫渐变）、陶土 `clay`（淡蜜桃纸、衬线标题）、杂志 `editorial`（淡天蓝纸、全衬线、居中刊头）、撞色 `poster`（柠檬黄封面、黑色页眉条）、纯黑 `ink`（黑底白线）、电光 `neon`（深蓝底、一抹电蓝、等宽标签）。干货清单选备忘 / 纯白，生活随笔、旅行选手帐 / 柔光 / 陶土，观点长文选杂志，要抓眼球选撞色，夜读选纯黑，数码、游戏、运动选电光。
- 想换颜色不换结构用 `apply_palette`（`list_palettes` 看配色库，或给三五个色值）；字号、行距、字体用 `set_style`。别每样都调：主题默认值通常就好。
- 长文（公众号式一整张长图）用 `set_mode` 切到 `article`。

## 4. 出图检查（get_pages / render_pages，必做）

- `get_pages` 列出每页放了哪些块、正文区用了多少和这一页的问题（⚠ 只有标题、太空、偏挤、溢出）；`render_pages` 附每页的 PNG。逐页看：
  - 一个要点被拆到两页（「转下页」）、页底只剩一个标题、某页只有一两行：在要点之间 `insert_page_break`，或 `move_section` 调顺序，或删减文字后 `update_draft`。
  - 页数太多（> 9）：压缩文字，而不是缩小字号。
  - 图片太高挤掉文字：`resize_image`（`widthPercent`）或 `crop_image`（`aspect: "3:4"`）。
- 改完再 `render_pages` 看一遍，直到每页都清楚、没有孤行。

## 5. 交给用户

- 告诉用户稿子已经在 Vibepost 里（标题、几页、用了什么主题），请他看一眼，需要的话直接在 App 里改字。
- 用户说要发时再 `send_to_iphone`：App 里会弹出隔空投送面板，**由用户在 Mac 上选自己的 iPhone**，你没法替他选，也不知道收没收到；小红书正文（`caption`）会放进剪贴板，发布时粘贴（空着时剪贴板不动，先写好它）。
- 用户要文件时用 `export`（`zip` 整组、`png` 单页、`long` 长图）写进他指定的、已经存在的文件夹；同名文件已经有了会报错，确认可以覆盖再给 `overwrite: true`。

## 出错时

- 「用户在 Vibepost 里切到了别的稿子」：用户在它的窗口里换了稿子或关了窗口，别抢；问他要改哪篇，再 `open_draft`（会用开着它的窗口，或开一个新窗口）。
- 「没有打开「允许外部 Agent 连接」」：这个开关默认是关的，请用户在 AI 助手 › 设置里打开。
- 「Vibepost 没有在 20 秒内准备好」「没能打开 Vibepost」：请用户打开 App（或装好 /Applications/Vibepost.app）后再试。
